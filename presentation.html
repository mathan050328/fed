Problem Statement
The Healthcare Data Dilemma

Centralized ML Challenges

  • Siloed Patient Records: Data is isolated across hospitals with restricted external access.
  • Regulatory Compliance: HIPAA and GDPR prohibit uninhibited sharing of identifiable records.
  • Vulnerable Single Point of Failure: Central data warehouses attract high-risk cyber attacks.
  • Data Sovereignty: Institutions refuse pooling due to legal liabilities and governance conflicts.

The Federated Solution

  • Decentralized Data Custody: Patient records never leave local hospital firewall boundaries.
  • Collaborative Training: Hospitals train local models on internal records independently.
  • Parameter Exchange: Only mathematical weights (coef_, intercept_) are transmitted.
  • Sample-Weighted FedAvg: Coordinator aggregates updates proportionally to client sample sizes.

Architecture
System Architecture & Federated Workflow

1. Data Isolation

3 distinct hospital data folders (client_1, client_2, client_3). No cross-access.

2. Local Training

Clients receive global weights, train for 5 local epochs on internal patient records.

3. Weight Uplink

Only numerical weight arrays and sample count (n_k) are uploaded. Zero CSV rows transmitted.

4. Server FedAvg

Central Flower server executes sample-weighted FedAvg and evaluates on held-out test data.

Principle: Server coordinates model aggregation blindly without access to client filesystems or raw clinical data.

Data Preprocessing
Clinical Dataset & Leakage-Free Preprocessing

UCI Heart Disease Dataset

  • Cohort Size: 303 de-identified patient instances.
  • Binary Target: 0 = No Disease, 1 = Heart Disease Present.
  • 13 Clinical Features: Age, Sex, CP, Blood Pressure, Cholesterol, FBS, RestECG, Max Heart Rate, ExAngina, Oldpeak, Slope, CA, Thal.
  • Split: 80% Train (242 samples for clients), 20% Held-Out Test (61 samples).

Leakage-Free Pipeline

  • Fit-Only-On-Train: ColumnTransformer fitted solely on training split; test set is only transformed.
  • StandardScaler: Z-score standardization for continuous numerical biomarkers.
  • OneHotEncoder: Expands categorical features to 30 encoded dimensions.
  • Persisted Preprocessor: Saved to preprocessor.joblib for Streamlit inference.

Mathematical Formulation
Federated Averaging (FedAvg) Formulation
W_{t+1} = ∑_{k=1}^K ( n_k / N ) W_{t+1}^k

Where K = 3 clients, n_k = local sample size, N = total samples (242), and W = [coefficients, intercept].

Why Sample-Count Weighting?

  • Prevents small diagnostic clinics from skewing weights against large hospitals.
  • Matches the mathematical objective of centralized empirical risk minimization.
  • Formally tested in test_fedavg_synthetic_weighted_average.

Warm-Start Optimization

  • Clients initialize local LogisticRegression directly from incoming global weights.
  • 5 local optimization epochs performed before sending parameter updates.

Security & Privacy
Privacy Boundaries & Threat Models

Guaranteed in Prototype

  • Zero raw CSV or patient rows transmitted across the network.
  • Model training strictly isolated within hospital client partitions.
  • Payloads verified to contain only float weight arrays and sample counts.

Advanced Threat Models

  • FL is Not Absolute Privacy: Gradient inversion or membership inference can theoretically probe model updates.
  • Defense 1 (DP-SGD): Calibrated Gaussian noise addition bounded by privacy budget (ε, δ).
  • Defense 2 (SecAgg): Cryptographic multi-party computation so server sees only aggregated sums.
